# 小组件视觉语法与设计参考

视觉调整只改变内容表达，不重排用户桌面、不增造统计口径；尺寸交互另按下文的组件自声明有限组合与吸附手柄契约执行，旧合法尺寸不自动转换。外部站点只作设计研究，不引入其依赖或复制付费源码。

## 公开参考与边界（2026-11-05）

- [BoardUI](https://www.boardui.com/zh-hans)：首页与公开目录包含指标卡、任务列表、贡献记录等；借鉴主值 / 上下文 / 分项的层级。具体 Pro 组件正文未完整获取，不声称复刻其像素设计。
- [Bencho](https://bencho.dev)：[进度跟踪](https://bencho.dev/blocks/progress-tracker)、[世界时钟](https://bencho.dev/blocks/world-clock)等公开描述展示局部操作反馈；借鉴短促反馈，不添加循环动画、假进度或时区拖动能力。
- [HeroUI Pro](https://heroui.pro)：公开首页强调一致的 typography / spacing / token 与多主题；借鉴统一 Widget / List / KPI 的结构纪律，不替换 DSH 控件。
- [beUI Pro](https://pro.beui.dev)：公开展示 AI Workspace / KPI / Approval Queue 类目与 reduced-motion 约束；借鉴运行、待处理与统计的语义分工，未读取收费源码。
- [Libraries.dev](https://libraries.dev/accessibility)：公开可访问性说明强调 reduced-motion、真实按钮与焦点、文本状态；不将边框光束或 WebGL 作为工作台常驻装饰。
- [Watermelon UI](https://ui.watermelon.sh)：公开 [dashboard 目录](https://ui.watermelon.sh/api/catalog/entries?kind=dashboards)给出概览、流转、复核类场景描述；具体页面只得到通用介绍，不据此声称已核对其视觉细节。

另生成一张独立设计参考并分析：深色清晰标题、单一主行动、平静列表、时钟主数字、便笺分隔编辑区、方形热图；仅采用这些视觉规则，未采用图中的虚构功能或数据。

## 落地

- 标题从浅色小字提高为清晰的主题主文字；内容最多三层，数字使用等宽数字。
- 最近会话用更紧凑的行与分隔，运行 / 待处理有语义色；未知和空闲保持中性。
- 今天强化主值，时间带弱化；回到现场强调继续操作，队列保留真实原因文字。
- 便笺正文与编辑入口分区，长内容局部滚动；时钟保留时区 / 日期及自己的时间选项。
- 快捷仅一个主要操作，其他行和编辑入口降低权重；任务仍然只准备未发送草稿。
- 工作足迹把活跃天数作为主值，范围与人工消息作为上下文；12 周使用固定 16px 方格，一年使用 12px，窄卡内部横滚，不再拉伸为长条。
- 仅消费 DSH 语义 token，保持宿主浅深主题；微反馈为 120ms，网格过渡为 150ms，reduced-motion 关闭过渡。普通拖拽、保存、配置与数据 API 不受视觉层修改。

## 参考图后的内容打磨

用户提供的 BoardUI 总览截图是本轮直接视觉参考：平静灰面、单一主值、对齐的行、有限分隔与明确操作区。另生成统计卡细节参考并分析，只采用层级与比例；图中的预计时长、场景等非现有字段不进入产品。

- 今天将活动时长、时间带和会话 / 轮数 / Agent 运行分层；把“专注”改称“活动时长”，移除无数据支撑的剩余时间归因。
- 工作区以右对齐时长与细条表示相对最大工作区的时长，不声称为全天时间占比；并行会话的簇可以重叠。
- 近两周加入中性轨道，卡片变高时增加实际绘图区；日期不拆成两行。
- 最近会话按实测正文高度估算首批容量，筛选 / 底部计数与滚动列表分离；较大字体或更多行仍可滚动，不隐藏不可见内容。
- 时钟字大小以卡片容器而非浏览器 vw 为依据；便笺、快捷、任务提示与待处理行使用有目的的内表面，避免多层描边。
- 工作足迹自动全年阈值由实际周数、固定方格、间距和内距共同计算；显式全年窄卡仍允许局部横滚。宽度变化不再反复抢回横向浏览位置。

## 组件自声明尺寸与组件库取舍

每个 widget 自己声明适合内容的有限网格组合，不采用宿主统一 12 档目录，也不使用尺寸下拉。推荐对象形式如 `sizing: { default: { w: 4, h: 6 }, supported: [{ w: 4, h: 6 }, { w: 7, h: 9 }] }`。宽是整数 `1..12`、高是整数 `3..30`，最多 16 个不同组合；默认值必须按 `w/h` 匹配其中一项。注册表克隆并深度冻结整个尺寸声明。完整输入、兼容与失败语义见[公共尺寸契约](<widget-development.md#5-组件声明的有限网格尺寸与配置限制>)。

- 新实例及拖入草稿用默认组合。旧 `defaults` 沿原范围校验后，以宽桶和真实 height 形成唯一组合，不向上取整或截断；旧 bounds 不提供连续几何权限，且不能与新 `sizing` 同时声明。0.17 字符串声明只作兼容，接受任意合法 `WxH`，不作为新代码推荐或用户尺寸目录。
- 12 列保持标称宽 `w`；6 列使用 `w <= 4 ? min(w, 3) : min(w, 6)`，2 列使用 `min(w, 2)`；高度不变，相同实际形状合并。正文响应式按实测像素宽高，而非兼容 `size` 桶判断。
- 编辑态右下角手柄按最近像素距离吸附声明组合；鼠标未松仅预览、不持久化，松手才 commit，Esc / blur / cancel 回起手尺寸。固定单组合且已匹配当前尺寸时不显示手柄；不同的旧保存尺寸仍可显式转换。尺寸手柄可聚焦，方向键可切组合。
- 改尺寸固定目标 `x/y`，只修改当前断点；碰撞或越界就拒绝，不挤动邻居、不自动换位。普通移动的碰撞让位与用户显式整理仍是不同操作。
- 旧合法保存矩形（含声明外宽高）保留；浏览、进入编辑、移动与整理不自动换尺寸。状态仍存各断点 `x/y/w/h`，不新增持久化尺寸身份，不改其他断点或缺失类型记录；仅有旧 order/size 的无坐标实例仍走历史 size 兼容。

声明组合须有实际内容收益：固定摘要 / 时钟避免无意义加高，列表按高度增加可见容量，便笺使用有限视口与局部滚动，工作足迹保留固定方格与窄卡内部横滚。选择 `supported` 前要检查中英文、窄屏、长标题、空满态和字体放大；不能只因几何合法就声称内容适合，不能靠裁掉编辑入口或关键数据来通过。此处规定契约与验收要求，不把历史视觉证据或已被纠正的 0.17 统一档位验收当作新尺寸手柄的验收；本次文档纠错不新增测试结论。

现成 dashboard widget 与 UI primitive 不是同一层：内置 widget 提供开箱即用的业务内容，扩展走注册表；基础控件继续复用宿主 UI primitives，不为外观引入另一套 UI 框架。内部可提炼 KPI / 列表 / 操作区模式，但不增加跨插件运行时耦合。

## 证据

真实安装 UI 的浏览器脚本为 `scripts/verify-widget-visuals.mjs`。数据是明确合成的 snapshot / activity 路由夹具，不是用户历史完整性审计；布局与配置写入走真实隔离宿主，finally 恢复。暗色使用临时 DOM 属性触发宿主主题别名，并不等于持久设置切换链路验收。
