# 0007 — 今日消费用余额差值算，不用 token 估算

- 日期：2026-11-10
- 状态：采纳

## 背景

余额卡想显示「今天花了多少钱」。平台只提供 `GET /user/balance`，返回总额 / 赠送 / 充值
三个数，**没有按天的消费明细，也没有账单接口**（官方只把余额当作快照，不做账单历史）。

本地能拿到的另一份数据是账本里的 token 天桶（input / output / cacheRead / cacheWrite）。
用它乘价目表也能得到钱，但那条路有三个问题：

1. 账本没有模型维度，也没有峰谷时段，价格表还得跟着官方调价维护——算出来的是估算，
   不是账单。
2. 只覆盖本机 dsh 会话；同一把 key 在别处（脚本、别的客户端）的消耗完全看不到。
3. 峰谷价差一倍，跨窗口的请求归哪一档官方自己也没写死。

## 决定

**用余额差值**，宿主侧记账：

- 每次真去平台读一次，就记一条 `{ at, total, toppedUp }` 到 `balance.json`；
  每天只留首尾两条，最多 45 天（一天 288 次读数不裁会撑爆文件）。
- 今日消费 = `(今天之前最后一条读数 + 今天新增的充值) − 最新读数`，结果小于 0 记 0。
- 今天之前一条读数都没有（首次使用）时，退到今天的第一次读数，`partial` 标出来。
- 卡片上它就是主值下面的一行：`今日消费 ¥0.42`；算不出来时这一行不出现。

充值必须补回去：不补的话，一次充值会把当天已经花掉的钱算成负数。

## 代价与失败模式

- **精度到分**，受平台两位小数限制；一天花几分钱也能看见，但也就这个粒度。
- **赠送额度过期**会让余额下降，被算成消费（只会高估，不会低估）。换 key、换账户同理。
- **没打开页面就没有读数**：基线是「今天之前最后一次读到的余额」，那天没打开过，差值就
  跨了几天，数字偏大。所以只叫「今日」，不承诺「零点起算」。
- 记账失败（磁盘满、只读）不影响余额本身：读数是账，余额是数。
- 「读数」是宿主真去平台的那一刻，不是页面渲染的时刻——缓存 5 分钟内的重复请求不会重复记账。
