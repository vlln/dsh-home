# 卡片一致性 · 普查与验收标准

> 目的：把「还有哪些卡没按 BoardUI 做过」变成一张可勾选的清单，并给每张卡写明**怎样算过关**。
> 规矩见 [`boardui-conformance.md`](boardui-conformance.md)：先看 BoardUI 有没有同类 → 有就采用 →
> 没有就自研，但只能用清单里已有的实测数字。

## 状态图例

- ✅ **已对齐**：结构照 BoardUI 做，实测值在清单里，有断言。
- 🔶 **部分**：卡壳/配色/字阶已对，仍有构件没量（环、格子、行、按钮组）。
- ⬜ **待普查**：还没逐项量过，可能只是碰巧像。

## 二、跨卡片的通用项（每张都要过）

1. **卡壳**：`.dsh-card`（16 圆角 / 16 内边距 / 无深色边框）。
2. **三段结构**：标题 14/500 secondary、主值 24/500 tabular + 同行单位、正文 12px 节奏。
3. **行**：一律 `Row*`（12px 内边距、14/500、分隔线）。
4. **图**：柱子 / 环 / 热力格 / 轨道，只用清单里量过的数字。
5. **空态**：`CardEmpty`，左对齐两行内，动作贴文字。
6. **不出现**：硬写像素字号、`var(--dsw-*)`、卡片自带边框、卡片内滚动条。

## 二·五、三张计时卡：判为自研，理由写死

`pomodoro` / `timer` / `countdown` 在 BoardUI 里**没有免费同类**，`activity-rings-card` 是 Pro
且注册表不返回源码（`r/activity-rings-card.json` → 404）。因此按协议第 4 步「表里没有同类才允许
自研」，它们**保留自研**，但只允许用清单里已量过的数字：

| 构件 | 取值 | 来源 |
|---|---|---|
| 环 | 描边 = 直径的 10%、round 端头、整圈轨道 | `activity-rings-card` 实测（第 3.7 节） |
| 环心数字 | `title-1`（24/500，tabular） | 卡片主值标准（第 1 节） |
| 倒计时主值 | `display-4`（32/500）+ 单位 `caption-1`（12/500）同行 | `stat-cards` 主值 32/500 的同一档 |
| 按钮组 | 自研：`Button size="small"` 并排 | 只用 vendored Button，不自画 |

### 最近会话 / 置顶：同一套行

两张卡共用 `SessionRow`，所以它们要么一起对、要么一起错——这也是把它们放在同一轮的原因。
行的内边距 12、字号 14/500、1px 分隔线全部来自 `data-table`（第 3.6 节），行高 32 是唯一
有意的密度偏差（表格 59 塞不进摘要卡）。

### 余额：为什么是 24 而不是统计卡的 32

`stat-cards` 的主值是 32/500，但那是一张**只有数字**的卡。余额卡除了金额还有一行说明
（`No API key configured`）与一个 `Refresh` 动作，属于「主值 + 细节」的摘要卡，所以取
卡片主值档 24/500。这条差异记在这里，是为了下次不用重新判断。

### 待办：行结构有意不用 `RowButton`

待办的每一行同时承载**勾选**和**就地编辑**两种交互，`Row` 的三段式（主标签/副标签/右端读数）
表达不了「点勾选框切换完成、点整行进入编辑」这个区分。所以这里保留自定义行，但只用清单里的数字：
勾选框 16/r4（第 3.8 节）、标题 14/500、分组标题 `data-table` 表头（14/500、不大写）。

### 图片：空槽用虚线框，不用空白

没有选图时，卡片给出一个**虚线圆角框 + 图标 + 「No picture chosen」**——这是全站唯一
用虚线的地方，理由：它是一个「待填充的槽」，不是内容。已在清单登记为有意例外。

槽的尺寸就是**卡片正文的尺寸**：虚线框占满正文区（不是一条 66px 的横带）。

点开「贴边铺满」后，**图片就是整张卡**：标题行、图标、16px 内边距全部让位，显示区域是卡片边框内的
整块（实测 756×324 的卡里图片 754×322，位于 1,1），圆角由卡片自己裁。编辑布局时标题行必须回来——
拖拽把手在里面，藏了卡片就动不了。

> 这类「整卡级」规则只能写在 `theme.css` 的 `components` 层。本项目的样式层序是
> `dsh-reset, dsh-legacy, theme, base, components, utilities`，所有手写组件 CSS 都在 `dsh-legacy`，
> 位置在最前，**在层序上永远输给 `components`**——无论选择器多具体。写在图片样式旁边那两轮，
> padding 一直是 16px、标题行一直在，原因就在这里。

选图**不做 data URL**：整份 widget 配置只有 **8 KiB**（`widget-registry.ts` 的 `WIDGET_JSON_LIMITS`），
图片字节永远进不了配置——把它塞进去，保存时只会得到「配置无效」。所以选中的文件由宿主的
`POST /api/dsh-home/picture` 落到 `$DSH_HOME/data/dsh-home/pictures/`（按内容嗅探类型、限 8 MB、
按 sha256 去重、0600），配置里只记一条短路径。
触发在卡片上——点图片或空槽直接开配置对话框，没有独立的「Picture options」按钮：
一个卡上只该有一个入口，按钮会把「卡片」和「卡片里的控件」混成两层。

### 配置对话框：宿主的容器用宿主的尺

对话框是宿主的 `Modal`（portal 到 `body`），卡片规则管不到它，所以它的规格来自宿主的 settings-form
（13/500 标签、34px 控件、12px 提示、行间 0.5px 分隔线，见 `boardui-conformance.md` 第 3.9 节）。
控件优先用宿主的 `Button` / `SegmentedControl` / `Switch`；字段框架用 `.dsh-modal-*`，不用卡片里的 `.dsh-item-*`。

已按此规格改造：图片、倒计时、语录。卡片内部的行内编辑器（待办编辑）仍用紧凑档，它不在对话框里。

### 便笺：三级文字，取自清单

| 角色 | 取值 | 来源 |
|---|---|---|
| 内容标题 | `text-body-medium`（14/500） | 卡片标题同档 |
| 正文 | `text-body-regular`（14/400 + 行高放宽） | 正文档 |
| 占位 | 同正文档、`text-tertiary` | 正文档降色 |

便笺是唯一的「阅读 + 编辑同一块区域」的卡，所以它不套 `Row`——行结构会给文本加不该有的分隔线。

### 时钟：为什么敢用 40/600

清单里最大的数字是 `stat-cards` 的 32/500。时钟用 40/600（`display-3-semibold`）是**唯一一处
超出清单字号**的地方，理由是：它整张卡只讲一件事（现在几点），时间必须能在一臂之外读出来，
而 32 在 380px 宽的卡里显得弱。这条记在这里，是为了下次有人问“为什么它不是 32”时不用重新吵一遍。

**这就是「定调」**：不是"没量所以随便"，而是"没有同类 → 记下这个判断 → 只用清单内的数字"。

## 二·六、第 26 轮收口：还没过的四张

| 卡 | 还差什么 | 卡在哪 |
|---|---|---|
| 工作足迹 | 格子是正方形，BoardUI 是 28×21；月份间隔未量 | 改了会改变一屏能排的周数，需先定宽度预算 |
| 计划 | 时间列宽、时间轴竖线未量 | 需要在 `data-table` 之外找同类（时间轴不是表格） |
| 今天 | 24h 轨的高度、刻度字号未量 | `progress` 的轨道是 `rounded-full` + 渐变高光，采用与否未决 |
| 日历 | 格子尺寸/圆角/今日标记未量 | 无同类，需要先决定「照 month picker 还是自研」 |

**结论：19 张里 15 张 ✅，4 张未过。按完成定义，现在不能说「首页已对齐 BoardUI」。**

## 二·九、一年的天数是日历的天数

`count === 365` 那条断言把实现常数当成了契约——它是垃圾代码，已删除。现在：

- `yearDays(today)` 看滚动一年里有没有 2 月 29 日：有则 366，无则 365；
- `year` 范围直接用它；`auto`（按周铺满）**只承诺不超过**当年的天数，因为整周会落在 365/366 之外；
- 断言改成行为式：格数 == 画出的天数、`year` 等于当年天数、`auto` 不超过它。

实测：`2026-11-09 → 365`、`2025-01-06 → 366`、`2024-03-01 → 366`、`2024-01-15 → 365`。

## 二·八、热力格：试过 4:3，退回正方形

按 BoardUI 的 28×21 做过一版 4:3，实际看下来像「网格拉伸坏了」而不是「他们的卡」——因为他们的
格子少、且行数固定；我们的是一年 52 周 × 7 天的高密度矩阵。**正方形在这里更易读**，记为有意偏差。

## 二·七、卡片不是按钮（2026-11-09，用户指出）

`.dsh-card:hover` 曾让整张卡在指针进入时变色——卡片看起来像一个巨大的按钮，卡片与内容的边界
随之消失。已删除：**交互反馈只属于指针下那一个元素**（行、柱子、按钮），不属于容器。

同轮还修了：行高 32 → 40（列表密度）、标题优先于工作区名（窄卡里直接隐藏工作区）、
删掉重复计数的页脚。

### 新增验收第 (f) 条：填充率

> 卡片要么被内容填到七成以上，要么随内容收缩；默认布局里不允许「两行内容 + 八行高」。

这条是因为上面那张卡五条全过、却仍是用户最先觉得难看的一张——清单里没有一条在问「填满了吗」。

## 三、验收标准

### 每张卡（逐项）

- [ ] 同类已查：`boardui-conformance.md` 的对照表里有这一行，并写明「采用 / 自研」。
- [ ] 用到的每个构件都在清单里有**实测值**（不是"看着差不多"）。
- [ ] 深色 + 浅色各一张真实渲染截图，无 console 错误。
- [ ] 该卡的断言进 `test/conformance.test.mjs`（几何/字号至少各一条）。
- [ ] 空数据下有结构（有主值或占位骨架），不是一块空白。

### 全局门禁（每次提交）

- [ ] `npm test` 全过（当前 482）。
- [ ] `npm run check:assets` 五项全过。
- [ ] `npm run build` 通过；`verify-host` 16/16。
- [ ] 打包安装到主 profile，`lib/client.js` sha256 与构建产物**一致**。

### 完成定义

全部 19 张卡的状态都是 ✅，且「已知还没量」一节为空。任何一张仍为 🔶/⬜ 时，
不得声称"首页已经对齐 BoardUI"。

## 四、建议顺序

1. **先补齐清单缺口**（成本最低、影响面最大）：`StatGrid` 内边距、`data-grid` 列头、浅色统计卡底色。
2. **同一族一起改**：三张计时卡（pomodoro / timer / countdown）共用环与按钮组，一次量完一起改。
3. **无同类的自研卡**（clock / notes / quote / countdown / picture / calendar / today）：
   逐张决定"改用 BoardUI 的某个原语"还是"保留自研但只用量过的数字"，并在对照表里写明理由。
4. **最后统一收口**：跨卡片通用项过一次，确保没有漏网的硬写值。
